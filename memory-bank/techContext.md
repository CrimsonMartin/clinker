# Technical Context

## Technology Stack

### Core Technologies

#### Frontend/Extension
- **TypeScript 5.8.3**: Primary language for type safety and better tooling
- **JavaScript ES2020**: Target compilation for broad browser support
- **HTML5**: Popup interface and content structure
- **CSS3**: Styling and responsive design

#### Browser Extension Framework
- **Manifest V3**: Latest extension standard for Chrome, Firefox, Edge
- **WebExtensions API**: Cross-browser compatibility layer
- **Chrome Extensions API**: Service workers, content scripts, storage

#### Backend & Cloud Services
- **Self-hosted Clinker sync API** (`server/`, contract in `docs/API.md`)
  - Email/password accounts; JWT access tokens (15 min) + rotating refresh tokens (30 days)
  - One JSON sync document per user with an integer `version` for optimistic concurrency
  - Default deployment: `https://clinker.lanerate.io`
- **Extension client** (`api/auth.js`, `api/sync.js`): plain `fetch`, no SDK

- **Node.js 18+**: Development environment and package management

### Build Process
1. **Environment Setup**: `build-config.js` writes `api/config.js` (`window.CLINKER_CONFIG`, `window.APP_CONFIG`)
2. **TypeScript Compilation**: `tsc` compiles `.ts` files to `dist/` folder
3. **Extension Loading**: `web-ext` loads extension in development browser
4. **Packaging**: `build-extension.js` copies files to `dist-chrome/` / `dist-firefox/` and sets
   `host_permissions` to the `API_BASE_URL` origin (root `manifest.json` keeps the default origin)

## Sync API Integration

### Authentication (`api/auth.js`)
- `POST /v1/auth/register|login` → `{user, accessToken, accessTokenExpiresAt, refreshToken}`
- Session stored in `storage.local`: `isLoggedIn, userEmail, userId, authToken, tokenExpiry, refreshToken`
- Access token refreshed ~60 s before expiry (timer + `ensureValidToken()`), and once more on a 401
- Refresh tokens rotate; concurrent refreshes in one page share a request, and a 401 on refresh
  first checks whether another extension page already stored a newer token before signing out
- `signOut()` → `POST /v1/auth/logout` (best effort) then clears auth + user data (`clearUserData`)
- `deleteAccount()` → `DELETE /v1/me`, then the same local cleanup (button on `login.html` account view)
- Sessions from pre-2.0 builds (no refresh token) are discarded; users sign in again

### Sync (`api/sync.js`)
- `GET /v1/sync` → `{data, version, updatedAt}` (404 = never uploaded)
- `PUT /v1/sync {data, baseVersion}`; 409 returns `{current}` → decision re-run against
  `current.data` and the upload retried once
- `data` = `{citationTree, nodeCounter, lastModified, userEmail, tabsMetadata}` (tabs flattened
  into one tree; `tabId` on each node)
- Newest-`lastModified`-wins decision logic unchanged from 1.x; last seen server version kept in
  `storage.local.syncVersion`

## Technical Constraints

### Browser Extension Limitations
- **Manifest V3**: No persistent background pages, service workers only
- **CSP Restrictions**: Limited inline scripts, external script constraints
- **Permission Model**: Explicit user consent for sensitive permissions
- **Storage Limits**: ~5MB local storage, unlimited with unlimitedStorage permission

### Sync API Limitations
- **Document size**: max 5 MB request body per sync document
- **Whole-document sync**: newest `lastModified` wins; no per-node merge
- **Polling**: 30 s auto-sync interval, no push notifications
- **Rate limits**: auth routes are rate-limited per IP

### Performance Constraints
- **Extension Startup**: <2 second target for initial load
- **Memory Usage**: Minimize background script memory footprint
- **Network Usage**: Efficient data sync, minimize redundant operations
- **Battery Impact**: Minimal background processing on mobile

## Security Considerations

### Data Privacy
- **Local Storage**: Sensitive data encrypted before storage
- **Sync server**: Data isolated per user (one document per account); account deletion removes it
- **Network**: HTTPS to the configured API origin only (manifest `host_permissions`)
- **Permissions**: Minimal required permissions requested

### Content Security Policy
```javascript
"content_security_policy": {
  "extension_pages": "script-src 'self'; object-src 'self';"
}
// No connect-src restriction, so fetch() to the API origin is allowed
```

### Authentication Security
- **Passwords**: Sent only to the sync API over HTTPS; never stored by the extension
- **Token Management**: `api/auth.js` refreshes and rotates tokens; tokens live in `storage.local`
